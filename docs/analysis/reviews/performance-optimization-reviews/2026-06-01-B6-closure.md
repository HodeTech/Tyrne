- **Hypothesis:** Re-baseline artefact, **with one hypothesis the measurement tested adversarially.** Per the [master plan's pre-flight](master-plan.md#pre-flight-hypothesis), no improvement target is set — the goal is the canonical post-B6 baseline. ## Baseline

### Methodology

- **Boot-to-end:** [`tools/perf-harness.sh`](../../../../tools/perf-harness.sh) `--release --iterations=20`, parsing the kernel's `boot-to-end elapsed = <ns>` line; min/p10/p50/p90/p99/max/mean/stddev by nearest-rank (`p99 == max` for `n < 100`). QEMU 10.2.2, `virt` + Cortex-A72, single-core, 128 MiB.
- **Same-host control:** the pre-EL0 commit `9551a33` (T-027 — the userland image is embedded but **dormant**, not run) was rebuilt in an isolated git worktree and measured with the same 20-iteration harness **back-to-back** on the same host, to separate the EL0-task cost from inter-session host drift.
- **Footprint:** `rust-size` (Berkeley) on the release BSP ELF.

### Metric 1 — Kernel image size

Release BSP ELF (`rust-size`, Berkeley `text` = `.text` + `.rodata`):

| Section | B5 closure | B6 closure | Δ |
|---|---|---|---|
| `text` (`.text`+`.rodata`) | 39,504 | **42,240** | **+2,736 (+6.9 %)** |
| `bss` | 50,592 | **64,240** | **+13,648 (+27.0 %)** |

The `text` growth is the B6 kernel surface (the high-half migration + gate #1 translate + gate #3 sourcing + `task_create_from_image` + the `syscall_entry` wire-up + `task_exit_current`) plus the embedded **117-byte userland image** (`.rodata`, via `include_bytes!`). The `bss` growth is dominated by new statics: `USER_TASK_STACK` (4 KiB) + the gate-#3 scheduler arrays (`task_cap_tables` / `task_user_windows`) + `USER_TASK_TABLE` / `FAILCLOSED_TABLE` + the high-half bootstrap page-table frames (T-022). All bounded, all `.bss` (zero file cost) — RAM, not image bytes.

Miri (`--workspace --exclude tyrne-bsp-qemu-virt`) **0 UB**.

### Metric 3 — Boot-to-end timing

Both bands, **same host, back-to-back**, 20/20 valid each:

| metric (ms) | **B6** (`c8792cf`, EL0 runs) | **Control** (`9551a33`, EL0 dormant) | Δ (B6 − control) |
|---|---|---|---|
| min | 12.727 | 13.934 | −1.21 |
| p10 | 13.143 | 14.110 | −0.97 |
| p50 | 15.507 | 15.978 | **−0.47** |
| p90 | 18.469 | 18.091 | +0.38 |
| mean | 16.019 | 16.253 | **−0.23** |
| stddev | 1.872 | 1.258 | — |

**Verdict on the hypothesis: refuted — running the first EL0 task adds no measurable boot-to-end cost.** The B6-vs-control delta (−0.23 ms mean; B6 is even *nominally lower*) is an order of magnitude below the per-band σ (~1.3–1.9 ms): the EL0 task's one-time round-trip + create + termination is **below the harness resolving floor**, precisely as predicted.

**This is why the control was essential.** The raw B6 band (p50 15.5 ms) is **lower** than the [B5 baseline](2026-05-29-B5-closure.md) (p50 20.3 ms) — which cannot be a real B6 *speed-up* (B6 only adds work). The same-host control resolves it: the freshly-rebuilt pre-EL0 binary **also** measures ~16 ms this session, so the ~5 ms drop vs B5 is **inter-session host drift**, not a B6 effect — confirming the [B5 finding](2026-05-29-B5-closure.md#what-we-learned) that the boot-to-end harness is at its resolving floor for B-phase-sized changes. Cross-session boot-to-end *absolute* comparisons are no longer meaningful at this granularity; **same-host deltas are.**

## Micro-measurements (EL0 round-trip / IPC / context-switch) — T-029

The boot-to-end harness cannot resolve the individual EL0 round-trip / IPC / context-switch costs (each ~µs, far below its ~ms floor). Measuring them directly uses a **feature-gated (`perf-bench`, off by default) measurement build** ([T-029](../../tasks/phase-b/T-029-perf-microbench.md)) that reads `CNTVCT_EL0` **kernel-side** around the cooperative primitives. The reads reuse the existing safe `Timer::now_ns` (UNSAFE-2026-0015) — **no new `unsafe`** and **no `CNTVCT_EL0` exposure to EL0** (T-029 AC#4). Build + run:

```bash
cargo build --target aarch64-unknown-none -p tyrne-bsp-qemu-virt --features perf-bench
# run the ELF under QEMU bounded by a timeout — it parks after printing the numbers
```

### Phase 1 — context switch + IPC (2026-06-01)

| primitive | QEMU-virt / TCG | composition |
|---|---|---|
| **context switch** | **3 595 ns/switch** (7 191 ns/round-trip) | one `yield_now` driver↔partner bounce = 2 switches; N = 50 000 round-trips (100 000 switches) |
| **IPC send→recv cycle** | **23 308 ns/cycle** | 1 `ipc_send_and_yield` + 1 `ipc_recv_and_yield` + 2 context switches; N = 50 000. Subtracting the 2 switches (≈7 191 ns) leaves **≈16 117 ns** of *pure* IPC (cap lookup + endpoint state machine + receiver unblock) |

**These are QEMU-virt TCG emulated-time figures, not real-silicon latencies.** QEMU's virtual `CNTVCT_EL0` advances on emulated time and TCG executes far slower than hardware, so treat them as **order-of-magnitude + relative** — the same harness-floor caveat the [B5 leg](2026-05-29-B5-closure.md) and §Metric 3 record. They are a baseline for *relative* regression tracking (e.g. "did a scheduler change move ns/switch?"), not absolute performance claims; real-hardware numbers await the Raspberry Pi 4 bring-up. Each figure is the mean over N = 50 000 iterations (after a 256-iteration warm-up), so *within-run* variance is negligible; the 16 ns counter granularity is ≪ the per-op cost. **Cross-run absolutes drift ≈20–25 % with host load under TCG** — a second run measured 2 816 ns/switch and 17 684 ns/cycle — so the figures above are one representative sample, not a stable absolute. The **stable, meaningful** signal is the *ratio* (an IPC round-trip costs ≈4.3–4.5× a context switch across both runs) and same-run deltas, which is what relative regression tracking uses.

### Phase 2 — EL0 syscall round-trip (pending)

The EL0↔EL1↔EL0 syscall round-trip — timed kernel-side around `syscall_entry` for a looping EL0 bench task, still **without** exposing `CNTVCT_EL0` to EL0 — lands in **T-029 Phase 2** (a separate PR), which will complete this section.

## Verdict

**Re-baseline, no regression.** B6 — including running the first real EL0 userspace task — adds **no measurable boot-to-end cost** (a same-host control proves the EL0-task delta is sub-floor, −0.23 ms ≪ σ). Footprint grows boundedly (+2.7 KiB `text` incl. the embedded image, +13.6 KiB `.bss` of new statics — RAM, not image). Test count +27 to 366; Miri 0 UB. The canonical post-B6 band is **p10/p50/p90 = 13.143 / 15.507 / 18.469 ms** (same-host; cross-session absolutes are below the harness floor). The per-op micro-measurements are T-029.
