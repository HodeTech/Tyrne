### Correctness

#### CODE-T034-R1-01 — HIGH — CI discards the production smoke failure through `tee`

**Locations:** `.github/workflows/ci.yml:237` and `.github/workflows/ci.yml:243` (the debug and release production smoke `run` pipelines).

Both steps run `tools/smoke.sh ... 2>&1 | tee ...` without a step `shell: bash`, a job/workflow `defaults.run.shell`, or `set -o pipefail`. On Linux the unspecified Actions shell invokes `bash -e {0}`; explicitly selecting Bash invokes `bash --noprofile --norc -eo pipefail {0}`. GitHub documents this distinction in its [workflow syntax reference](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsshell). The child smoke script's own `set -euo pipefail` does not set options in the enclosing workflow shell.

**Impact:** A missing required marker, forbidden release greeting, panic/fault trace, or another smoke-script failure can print `FAIL` and exit nonzero while `tee` successfully saves the log and makes the production step succeed. The subsequent negative harness invokes the smoke script directly via `subprocess.run`, so its 23 passing cases do not prove that the production workflow propagates failures. A green hosted run of the clean kernel does not establish that a bad production guest blocks merging. This violates the core T-034 merge-gate acceptance criterion.

**Independent proof:** A disposable QEMU stub emitted only `tyrne: all tasks complete`; the actual unmodified `tools/smoke.sh --int --timeout 1 <private-elf>` printed both missing greeting and missing task-exit diagnostics. Wrapped in the production-equivalent pipeline, `bash -e` returned **0**. The identical pipeline under `bash --noprofile --norc -eo pipefail` returned **1**. Evidence: `/tmp/tyrne-b21-t034-round1-code-pipeline.json`. The SECURITY reviewer first raised the candidate; this CODE reviewer independently reproduced it with the actual smoke entry point and checked the official shell contract.

**Required correction:** Enable `pipefail` for both production pipelines, preferably through job-scoped `defaults.run.shell: bash` or explicit `shell: bash` on both steps. Add a focused regression that exercises a deliberately rejected smoke trace through the workflow's effective shell and `tee`, asserts a nonzero enclosing result and the intended smoke diagnostic, and retains the diagnostic artifact. Testing only direct smoke subprocess exit codes misses this integration defect.
