## First increment — R2-SF01 and R2-SF02

The coordinator verified the reported behavior against [Python's documented URL normalization changes](https://docs.python.org/3.13/library/urllib.parse.html#urllib.parse.urlsplit), [CommonMark physical lines](https://spec.commonmark.org/0.31.2/#characters-and-lines) and [HTML URL input cleanup](https://url.spec.whatwg.org/#concept-basic-url-parser). Markdown angle/numeric-reference destinations must retain the selected source contract's decoded characters consistently across supported interpreters. HTML href/src cleanup has a separate explicit context; HTML tabs/newlines being removed is specified behavior, not itself a decoder finding. No universal renderer/browser parity is claimed.

Eight new fixture methods precede the parser changes. The first six-method tests-only revision on the frozen parser produced 24 failures on actual Python 3.9.6 and 36 on actual Python 3.13.14. A subsequent tests-only revision separated physical diagnostics from the earlier CR reference assertion and added invalid-UTF-8 offsets: its two selected methods produced two CR-only failures on 3.9. Earlier subtests stop at their first failed assertion; later positive/control behavior is not inferred from those failing runs. [Tests-first source validation](2026-10-13-t056-parser-evidence/r2-url-lines-source-validation.json) binds both actual uncommitted test revisions and their raw outputs to the unchanged frozen parser/CLI hashes.

Local URL delimiters are split without implicit normalization. Markdown retains leading spaces/C0 and decoded tab/newline scalars; HTML href/src explicitly trims leading/trailing C0/space then removes ASCII tab/CR/LF, before external classification and percent decoding. Percent-encoded characters remain distinct and are never trimmed again. Actual-versus-decoy inline/image/reference/HTML and percent-encoding controls cover these boundaries.

A shared LF/CR/CRLF iterator replaces Unicode `splitlines` in blocks, code-span boundaries, container/reference continuation, headings and source-line bounds. Lone CR becomes LF in the parsing view at the same character offset; CRLF retains its length, the original document text remains available, and HTMLParser's LF positions agree with physical diagnostics. Invalid-UTF-8 locations use the same three byte-level endings. Eight other Unicode/control separators cannot manufacture headings or source lines. Real LF/CR/CRLF headings, references/fences, source-line bounds and Markdown/HTML/error diagnostic locations are exercised.
